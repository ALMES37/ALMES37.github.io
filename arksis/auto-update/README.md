# Как сайт АРКСИС сам берёт фото и видео из группы ВК

Алексей спросил, можно ли добавлять новые фото и видео без программиста. Можно, и ничего нового учить не придётся: сайт забирает посты из группы ВК, куда они и так выкладывают объекты каждые 3–5 дней.

## Как это выглядит для Алексея

1. Публикует пост в группе как обычно: фото, видео, текст.
2. Добавляет в текст хэштег **#насайт**.
3. Примерно через час пост появляется на сайте в блоке «Свежее с объектов». Первое фото поста становится обложкой карточки, поэтому лучшее фото ставить первым.

Убрать пост с сайта: удалить хэштег из поста. Через час карточка исчезнет.

## Как устроено внутри

- Раз в час запускается бесплатная задача GitHub Actions (`vk-sync.yml`).
- Скрипт `vk_sync.py` спрашивает у ВК последние 100 постов группы и берёт только посты с #насайт.
- Фото и обложки видео он скачивает к себе в `img/feed/`. Ссылки на картинки ВК со временем перестают работать, а копии на сайте живут столько, сколько нужно.
- Всё складывается в один файл `data/vk-feed.json`. Сайт показывает карточки из этого файла. Видео открываются плеером ВК прямо на сайте.
- Если новых постов нет, ничего не меняется и сайт не трогается.

## Что нужно для запуска (один раз, 15 минут)

1. Создать приложение ВК на id.vk.com (тип «Веб») от аккаунта, которому доверяют. Скопировать **сервисный ключ доступа**. Он даёт только чтение открытых данных и не даёт управлять группой.
2. В репозитории сайта: Settings → Secrets and variables → Actions → New repository secret. Имя `VK_SERVICE_TOKEN`, значение ключ из п. 1.
3. Положить `vk-sync.yml` в `.github/workflows/`, скрипт в `auto-update/`.
4. Нажать Actions → «Посты из ВК на сайт» → Run workflow, проверить, что посты появились.

## Безопасность

- Ключ ВК лежит только в секретах GitHub. Его нет ни в коде страницы, ни в файлах сайта, ни в логах: скрипт отправляет его в теле запроса.
- Сайт не обращается к ВК за данными из браузера посетителя, он читает свой готовый файл. Ключ посетитель увидеть не может.
- Текст постов выводится на страницу как обычный текст (`textContent`), никакой HTML из поста не исполняется.
- Картинки скачиваются только с серверов ВК, не больше 8 МБ каждая.
- У задачи права только на запись в свой репозиторий.

## Сколько стоит

- GitHub Actions для этой задачи бесплатен: один запуск длится меньше минуты, бесплатного лимита хватает с запасом.
- API ВК бесплатный.
- Остаются обычные расходы на сайт: домен и хостинг. Отдельной платы за обновления нет.

## Где может сломаться и что делать

- ВК поменяет API: раз в год-два нужно проверить версию API в скрипте (сейчас 5.199).
- Ключ ВК отзовут или удалят приложение: посты перестанут приходить, сайт продолжит показывать последние. Создать новый ключ и заменить секрет.
- GitHub выключает задачи по расписанию, если в репозитории 60 дней нет изменений. Скрипт раз в 30 дней обновляет отметку проверки, поэтому этого не случится.

## Почему выбран этот вариант

| Вариант | Плюсы | Минусы | Надёжность |
|---|---|---|---|
| **Посты из группы ВК (выбран)** | Алексей ничего нового не учит, контент уже есть, видео работает, 0 ₽ | Обновление с задержкой до часа, нужен хэштег | Высокая: если ВК недоступен, сайт показывает последние посты |
| Админка Decap CMS | Можно править любой текст сайта | Нужен аккаунт GitHub и отдельный вход, фото грузить второй раз, видео в репозиторий не положить | Средняя: нужен свой сервер авторизации |
| Google Таблица | Привычная таблица | Фото надо где-то хранить и вставлять ссылками, таблицу легко сломать, Google в России работает с перебоями | Низкая |

## Хостинг

Набросок лежит на GitHub Pages только для показа. Рабочий сайт должен жить на домене клиента: правила GitHub не разрешают держать на Pages сайт коммерческой компании. Схема та же: репозиторий на GitHub, задача раз в час обновляет посты и выкладывает сайт на хостинг клиента по FTP или SSH. Пароль от хостинга тоже хранится в секретах.
